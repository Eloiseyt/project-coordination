# 来源与适用限制

检索日期：2026-10-13。以下是设计参考，不是本技能获得认证或保证效果的证据。规则是针对协作失误形成的工程取舍；没有声称一种组织方式在所有项目最优。

| 一手来源 | 采用的有限启发 | 不能外推的结论 |
| --- | --- | --- |
| [Agent Skills specification](https://agentskills.io/specification) | 使用标准技能入口与按需参考文件 | 格式合规不等于行为可靠或安全认证 |
| [Anthropic: Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) | 从简单组合开始，复杂度由任务需要决定 | 不是必须采用某供应商、框架或固定代理数量 |
| [Anthropic: Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) | 委派需清楚边界、原始证据和可评估结果；协调和 token 有成本 | 研究系统的效果或成本数字不能直接套到软件项目 |
| [Skills directory documentation](https://skills.sh/docs) | 了解公开技能的发现与安装渠道 | 被目录收录或安装次数不代表官方质量背书 |

未复制这些文章的正文或代码。该技能不包含项目密钥、内部聊天、真实用户文件或固定机器路径；示例是通用场景。

本技能本身不启动后台任务、不创建代理、不修改权限、不上传文件。使用者仍需在自己的环境内明确授权；工具不可用时退化为同一代理维护分工与状态。

采用项目语言和既有结构；TypeScript 是项目采用它时的约束，不强迫 Python、Go 或其他项目迁移语言。报告语言和频率按用户偏好；不要把某个用户喜欢完整表格误变成所有任务必须长篇汇报。

验证层次：格式检查、链接/隐私检查、独立情景演练、真实项目试用分别记录。情景演练不能证明 token 节省或所有团队稳定性。版本更新应由实际失误或用户反馈驱动，修订后复测受影响场景，避免不断追加重复规则。
