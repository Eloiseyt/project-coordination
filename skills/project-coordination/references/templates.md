# 记录模板

按需复制到项目现有记录；不要一次创建所有文档。方括号表示需要由项目事实填写的字段，不是可直接执行的指令。

## A. 项目协作约定 / 主检查点

```text
修订/更新时间：
项目/环境/版本：
目标与当前最小可用结果：
明确非目标、保护数据：
有效用户授权及来源：
唯一整合负责人：
报告约定：语言、详细度、累计表范围、通知触发
领域负责人和证据位置：
累计要求：稳定编号、原始来源、当前验收、替代关系
任务表：编号/状态/owner/依赖/证据层与版本/缺口/下一步
共享归属：路径或外部资源/写入者/范围/基线/释放状态
在途或未知操作：
最新决策与原因：
恢复第一步：
```

没有并行任务时删去多余栏目。大项目可以链接专门账本，但不要复制同一事实到两份“主检查点”。

## B. 可执行工单

```text
工单/关联要求/修订：
用户可验收的结果：
当前基线、已有事实、关键不确定项：
原始资料和必须读的约束：
允许读写范围；不得动的范围：
接口输入/输出、消费者和兼容要求：
所需验证与真实样本边界：
依赖与共享锁：
可自主决定的事；必须回报/停止的条件：
预算/时间窗口（仅在用户或项目实际设定时填写）：
是否允许子代理、最大并发及其范围（按授权填写）：
交付位置、检查点、下一汇报节点：
```

派发消息可以短，但不能省掉对结果、边界和证据的约定。没有新的费用/风险/接口变更，执行者在工单内自主推进。

## C. 领域节点回报

```text
工单/修订/当前版本：
本轮已改变：
已验证行为及证据位置：
未验证或相反证据：
修改文件/共享差分/无关dirty保护：
依赖或越界风险：
下一步：继续 / 待有界审查 / 需特定决定 / 安全暂停
在途操作或未知结果：
```

## D. 审查结论

```text
审查者、时间、候选版本/差分：
覆盖范围与未读项：
发现：位置、触发、影响、证据、建议的最小修正
判断：可按该范围继续 / 有条件继续 / 先修阻塞
需要补的验证：
不需要重复的既有验证：
```

## E. 正式用户报告

```text
整体判断：当前能用到哪一步，是否需要调整方向。
本轮变化：只列真实新增或改变的结论。

| 编号/问题及必需验收 | 已做与本轮变化 | 状态/环境/版本/时间/证据来源 | 剩余问题 | 下一步/负责人 |
| ... |

协调决定：接口、所有权、优先级或计划有什么变化，为什么。
需要用户决定：具体选项和取舍；没有则不制造请示。
证据：少量可点击的主证据入口。
```

## F. Bug 卡片

```text
问题/关联需求：
现象、预期、影响：
版本/环境/最小输入：
事实；假设；还缺的证据：
第一个出错边界及根因证据：
最小修复/非目标/责任人：
回归及原场景复验：
状态、剩余限制、是否进入本轮交付：
```

## G. 暂停与接班回执

```text
暂停范围/用户指令来源：
每位执行者：确认时间、已停或仍在途、保存位置
相关监督：已暂停 / 未能确认 / 不存在
最后已知代码和环境版本：
dirty/写入归属及保护数据：
未知操作结果：
最后通过的验证及未验证项：
恢复条件、第一步及有权恢复者：

接班时追加：接收者、核实事实、未读/冲突、接收确认、权责切换记录
```
